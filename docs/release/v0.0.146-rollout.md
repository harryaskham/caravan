# Cara v0.0.146 — the queue repairs Stacks holding closed history

## Why

On 2026-10-21 every `cara-sync-cacophony` tick from 10:40Z exited 1 with
`github_stack_closed_history_requires_owner` on native Stack #4597. The Stack
kept merged #4595, #4596, #4598 and #4601, then a stale flake bump (#4600, later
closed unmerged) and #4603, which had diverged from #4600 and conflicted with
main. With `max_caravans: 1` that caravan held the only slot, so #4604–#4606
were refused as incompatible with tail #4603 until an operator rebased and
merged by hand. The v0.0.144 drift repair (bd-7ff76d) did not cover Stacks that
keep closed history, and it left a conflicting member quarantined in its slot.

## Changes (bd-7efe6a)

- Under the repository's reviewed `stack_rollout.mutations_opt_in`, and unless
  `stack_rollout.manual_drift_repair: true`, sync rebuilds one Stack per tick
  whose retained closed rows defeat automatic merged-prefix recovery
  (closed-unmerged rows, history interleaved after the open suffix, or
  non-linear open ancestry). It runs before that recovery would refuse the whole
  tick. Eligibility is exact: open drifted Stack, one mapped unpaused unparked
  caravan, provider-closed retained rows, open rows that are all members of that
  caravan, and only ancestry, PR base/head, member-order, missing-closed-row,
  merged-prefix or state-order problems. Unknown ancestry, Stack base drift,
  orphaned or terminal Stacks never qualify.
- The rebuild uses the existing sealed planner and publisher (actor
  `caravan-scheduler`): every active member is replayed linearly from the exact
  default branch under force-with-lease against its observed head (a root still
  based on a closed row binds that row's immutable `refs/pull/N/head`), the
  drifted Stack is cleared, each survivor's PR base is pointed at its linear
  predecessor, and only the survivors are rebuilt. Closed rows are pruned from
  the representation, never rewritten; the raw generation stays in the sealed
  plan, the checkpointed receipt and the tick output. An applied plan hash is
  never replayed.
- For this rebuild and the routine drift repair alike, a member that cannot be
  replayed linearly (content conflict or unreplayable history shape) is evicted
  together with its descendants, tail-first and labels-only, with a typed
  reason; heads and bases are preserved and the members before it keep their
  rebase. Fetch, timeout, lease, missing-object or push-preflight failures never
  evict.
- The tick emits `evicted` and the existing `sync_failed` event with
  `metadata.error_code: native_stack_member_unreplayable`,
  `metadata.pull_request`, and a typed `metadata.repair_request` (exact PR,
  head, base, attempted target, refusal, conflicting paths, evicted PRs, and the
  suggested `cara repair start --pr N [--target-pr P] --non-force …` then
  `cara rejoin --pr N`).
- `cara sync --dry-run` previews the same sealed plan hash as a
  `native_stack_repair` action and stops there, like the tick.
- `github_stack_closed_history_requires_owner` now names `recovery_caravan_id`;
  it still fails closed where the queue may not repair (for example
  `manual_drift_repair: true`, a paused or parked caravan, or unknown ancestry).

Hermetic fixtures cover the closed-history prune and linear replay (including the
exact Cacophony #4597 singleton shape), policy and fact gating, eviction of a
conflicting suffix with its repair request while capacity is freed, idempotent
replay of an applied plan hash, dry-run plan parity, tail-first labels-only
eviction, and immutable range binding for a root based on a closed row.

## Rollout

No configuration change is needed: repositories that already opted into Stack
mutation get the new behaviour. `stack_rollout.manual_drift_repair: true`
restores the owner-only policy for both repairs.

The version bump lands with the change through the normal reviewed queue. It
does not itself publish a release. After required CI and provider-confirmed
merge, a release owner should follow the
[canonical release procedure](../../README.md#releases-and-self-update):

```sh
just release-tag v0.0.146 <exact-landed-commit>
# Wait for the immutable tag's release workflow and verify published assets.
just release-pin-rows v0.0.146 "bd-7efe6a queue-owned closed-history Stack repair"
```

Then report the verified version to the Cacophony controller so its
`cara-sync-cacophony` pin can advance; Stack #4597 (or its successor shape) is
repaired by the first tick that runs v0.0.146.
