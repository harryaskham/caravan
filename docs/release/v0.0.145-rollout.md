# Cara v0.0.145 — unproven readiness observations

## Changes

- `DeferredAdmissionReason` adds distinct `run_unproven` and
  `unknown_membership` wire values (bd-0d5e4b).
- The bounded `cara-admission-unevaluated` log reader accepts both reasons.
  Neither implies a membership race, positive unjoined evidence, or membership
  success. Existing `membership_changed`, `draft`, and historical unjoined
  receipts retain their wire format and behavior.
- Sync treats a proven gate-only receipt as unevaluated, never green or a
  source verdict. Independently enrolled members use the existing exact-gate
  refresh and active-run reuse path.
- Exact PR/head/base, native reporting App/job binding, complete bounded logs,
  and the runner's actual exit 78 remain required. Exit 1, wrong identities,
  duplicate/malformed/truncated markers, and independent source failures do not
  gain an admission exemption.

Parser and sync regression fixtures cover both reasons, labelled and unlabelled
PRs, exact-run recovery/reuse, wire round trips, and the negative controls above.
The observer's `run_unproven` decision still runs heavy CI; this release changes
only recognition of the separate readiness reporter's unevaluated receipt.

## Release continuation

The version bump lands with the correction through the normal reviewed queue.
It does not itself publish a release. After required CI and provider-confirmed
merge, a release owner should follow the [canonical release procedure](../../README.md#releases-and-self-update):

```sh
just release-tag v0.0.145 <exact-landed-commit>
# Wait for the immutable tag's release workflow and verify published assets.
just release-pin-rows v0.0.145 "bd-0d5e4b reviewed readiness correction"
```

The tag helper verifies canonical GitHub main containment and exact package
versions and refuses an existing tag; never move or reuse a published tag.
Verify the release archives/checksums for all supported targets before claiming
complete publication. Cacophony's initial bd-b172e8 adoption stays on 0.0.144;
a follow-up may advance its pin and enable these two reporter reasons only
after the corrective release and its assets are verified.
